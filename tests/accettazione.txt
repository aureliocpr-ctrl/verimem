# The acceptance suite: one test file per line.
#
# WHAT IT IS. The files that exercise a PORT of the product from the outside
# (`open_memory()`, the CLI entry point, the MCP tool dispatch) on the two core
# operations -- write a fact with its source, recall it -- plus the verdict and
# the receipt that go with them. Everything else is not in here: neither the
# tests that call an internal function directly, nor the ports of the tools
# around the core (dreams, skills, episodes, swarm, dashboard, entities).
#
# HOW TO RUN IT.  pytest -m accettazione
#
# HOW IT IS BUILT. A file enters WHOLE, not test by test: a parametrised node id
# changes whenever a case is renamed, and a list of node ids would rot in
# silence. The price, stated: the suite also picks up the tests that sit next to
# the core ones in the same file, so the number collected is larger than the
# number of core tests that selected the file.
#
# THE GUARD. A line here that matches no collected file FAILS the collection
# (tests/conftest.py). A list that rots quietly is a disconnected sensor, and
# this suite is the one thing that must not go green by being empty.
#
# Measured 2026-09-16 on 9991 test functions: 887 touch a port, 345 of those are
# on the core, and they live in the 85 files below.
